    Sprint 0¶

    1. Contexto do projeto¶

    O KeepUnB é um sistema desenvolvido para auxiliar na organização e no acompanhamento de solicitações de manutenção dentro do ambiente universitário da UnB.

    Antes da proposta do sistema, o controle de chamados de manutenção era pensado como um processo pouco centralizado, com dificuldades para registrar solicitações, acompanhar o andamento dos atendimentos e organizar a distribuição das demandas entre os responsáveis.

    A partir desse cenário, identificamos a necessidade de criar uma solução digital que facilitasse a comunicação entre solicitantes, gerentes e técnicos, tornando o processo mais claro, rastreável e eficiente.

    2. Problemas iniciais identificados¶

    Durante o estudo inicial do produto, foram identificados alguns problemas principais:

    • Falta de um sistema centralizado para abertura e acompanhamento de chamados;
    • Processo manual ou pouco padronizado para registrar solicitações de manutenção;
    • Dificuldade para o gerente visualizar, organizar e atribuir chamados aos técnicos;
    • Falta de clareza sobre o status de cada manutenção;
    • Ausência de histórico estruturado dos chamados realizados;
    • Comunicação descentralizada entre solicitantes, gerentes e técnicos;
    • Dificuldade para acompanhar o desempenho e o andamento das demandas.

    Esses problemas poderiam causar atrasos, perda de informações, retrabalho e baixa transparência no processo de manutenção.

    3. Proposta de solução¶

    Para resolver esses problemas, propusemos o desenvolvimento do KeepUnB, uma aplicação web voltada para o gerenciamento de chamados de manutenção.

    A solução foi pensada com três perfis principais de usuário:

    • Solicitante: responsável por criar chamados informando o local, o tipo de manutenção e a descrição do problema;
    • Gerente: responsável por visualizar os chamados e atribuir técnicos disponíveis para cada demanda;
    • Técnico: responsável por acompanhar os chamados atribuídos e atualizar o andamento da manutenção.

    Com essa divisão de perfis, o sistema organiza melhor as responsabilidades de cada usuário e torna o fluxo de atendimento mais controlado.

    4. Como buscamos resolver o problema¶

    A equipe decidiu resolver o problema por meio da criação de um sistema digital com fluxo padronizado de chamados.

    O fluxo principal definido foi:

    Solicitante cria chamado → Gerente atribui técnico → Técnico atualiza andamento

    Além disso, o projeto foi estruturado para oferecer:

    • Cadastro e organização dos chamados de manutenção;
    • Separação de permissões por perfil de usuário;
    • Páginas iniciais específicas para solicitante, gerente e técnico;
    • Acompanhamento do status dos chamados;
    • Registro das informações principais de cada solicitação;
    • Base para geração futura de relatórios e métricas.

    Dessa forma, o KeepUnB busca transformar um processo descentralizado em um fluxo mais organizado, transparente e fácil de acompanhar.

    5. Resultados esperados¶

    Com a implementação do KeepUnB, espera-se que o processo de manutenção se torne mais eficiente e confiável.

    Os principais resultados esperados são:

    • Maior organização na abertura e no acompanhamento de chamados;
    • Redução da perda de informações;
    • Melhor distribuição das demandas entre os técnicos;
    • Mais clareza sobre o andamento de cada manutenção;
    • Facilidade para consultar o histórico de solicitações;
    • Melhoria na comunicação entre os envolvidos;
    • Apoio à gestão por meio de dados mais estruturados.

    6. Conclusão¶

    A Sprint 0 foi importante para entender o problema, definir o escopo inicial do produto e estabelecer a proposta de valor do KeepUnB.

    A partir do estudo de caso, a equipe identificou que o principal desafio era a falta de padronização e centralização no processo de manutenção. Como resposta, foi proposta uma solução web capaz de organizar os chamados, separar responsabilidades por perfil e permitir o acompanhamento das solicitações de forma mais clara.

    Assim, o KeepUnB surge como uma ferramenta voltada para melhorar a gestão de manutenção no ambiente universitário, oferecendo mais controle, transparência e eficiência ao processo.
